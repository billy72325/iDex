# 在 GX10 上訓練 1025 類辨識模型

從 Mac 搬到 GX10（ASUS Ascent GX10 / DGX Spark，GB10 + aarch64）後要做的事，照順序。

## 1. 搬檔案

需要兩樣東西：repo 本身（`upgrade` 分支）和訓練資料 `artifacts/national/`（1.26 GB，不在 git 裡，放在 GitHub Release）。

```sh
# 在 GX10 上
git clone -b upgrade https://github.com/billy72325/iDex.git ~/iDex
cd ~/iDex && mkdir -p artifacts

# 下載訓練資料（Release: raining-data-v1）
curl -L -o national-artifacts.tar \
  https://github.com/billy72325/iDex/releases/download/raining-data-v1/national-artifacts.tar
echo "83dc18e40182b2c2b652cb0af3120fdee72450c930db8544f0a57fa081555653  national-artifacts.tar" | sha256sum -c
tar xf national-artifacts.tar -C artifacts/ && rm national-artifacts.tar
```

Mac 和 GX10 在同一個網段的話，直接 `rsync -avh ~/iDex/artifacts/national/ gx10:~/iDex/artifacts/national/` 也可以，結果一樣。

搬完確認：

```sh
ls artifacts/national/sources/JJMack--pokemon-classification-gen1-9/   # train/test/validation.parquet
ls artifacts/national/sources/torchvision/                             # 三個 .pth
cat artifacts/national/data/summary.json                               # images 17914, missing_species []
```

有 `data/manifest.jsonl` 就不會再重做解碼；沒有的話 `run.sh` 會自己跑 `prepare.py`（約 15 分鐘）。

## 2. 進 NVIDIA PyTorch 容器

GX10 是 aarch64，用 NVIDIA 的容器最省事，CUDA 版 PyTorch 已經裝好：

```sh
cd ~/iDex
docker run --gpus all -it --rm --ipc=host -v "$PWD":/work -w /work nvcr.io/nvidia/pytorch:25.10-py3
```

進容器後（容器是 `--rm`，**每次重開都要再做這三行**）：

```sh
git config --global --add safe.directory /work      # repo 是 host 使用者的，容器內是 root
pip install pyarrow pillow numpy
python -c "import torch; print(torch.cuda.get_device_name(0))"   # 要看到 GB10
```

之後要更新程式碼：`git fetch origin && git reset --hard origin/upgrade`。

不想用 docker 的話，開一個 venv，照 https://pytorch.org/get-started/locally/ 裝 CUDA 13 的 aarch64 wheel，然後 `export IDEX_TRAIN_PYTHON=~/venv/bin/python`。

## 3. 訓練

```sh
bash scripts/national/run.sh efficientnet_b0 20
```

這一行會依序：確認 GPU → 檢查資料（已有就跳過下載和解碼）→ 訓練 20 個 epoch → 用驗證集跑預測。EfficientNet-B0、224 px、batch 128，在 GX10 上一個 epoch幾分鐘，整輪一小時內。

中途想停：Ctrl+C，之後同一行指令會從 `last.pt` 續跑（`run.sh` 帶了 `--resume`）。

要調參數直接呼叫 `train.py`：

```sh
python scripts/national/train.py train --arch efficientnet_v2_s --epochs 30 --size 256 --batch 96 \
    --out artifacts/national/runs/effv2s-256
```

可選架構：`efficientnet_b0`（預設，最小、最快）、`mobilenet_v3_large`、`efficientnet_v2_s`（較強，匯出後約 80 MB）。

## 4. 看結果

```sh
cat artifacts/national/runs/efficientnet_b0/run_status.json          # best_top1
tail -3 artifacts/national/runs/efficientnet_b0/history.jsonl         # 每個 epoch 的 loss / top1 / top5
cat artifacts/national/predictions/efficientnet_b0-val.summary.json   # 整體 top1 + 最差 25 種
```

判斷基準：驗證集 top-1 應該要在 0.85 以上才值得放進 app；`worst_species` 幾乎都會是第八、九世代那 66 隻圖片少於 5 張的物種，正常。若整體明顯偏低，先試 `efficientnet_v2_s` 或 `--size 256`。

## 5. 帶回 Mac 的東西

只要兩個檔案：

```
artifacts/national/runs/<arch>/best.pt
artifacts/national/predictions/<arch>-val.summary.json
```

回到 Mac 後照 `scripts/national/README.md` 的「Bringing the model back into the app」用 `export.py` 轉成 Core ML，再換進 `iDex/Recognition/`。這一步需要 macOS + coremltools，不能在 GX10 做。

## 常見狀況

- `CUDA GPU required`：沒在容器內，或 docker 沒帶 `--gpus all`。
- `detected dubious ownership`：容器內沒做 `git config --global --add safe.directory /work`。
- `No module named 'pyarrow'`：容器重開後沒再 `pip install`。
- `cannot identify image file`：某張解碼圖壞了；`python scripts/national/prepare.py` 會檢查並重做壞掉的圖。
- `checksum mismatch`：rsync 傳到一半；重新 rsync 那個檔案。
- `labels must be unique and sorted`：`pokemon_labels_national.json` 被改過；`git checkout` 還原。
- 記憶體不夠（GB10 是 128 GB 統一記憶體，通常不會）：加 `--batch 64`。
- `artifacts/` 整個都在 `.gitignore`，訓練結果不會被 commit，也不要 commit。
